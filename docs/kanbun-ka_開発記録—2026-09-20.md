# kanbun-ka 開発記録 — 2026-09-20

## プロジェクト概要

**kanbun-ka**（漢文化）は、現代日本語を古典漢文（文言文）に自動変換する
Rails Web アプリケーション。

- リポジトリ: `toghisumasu/kanbun-ka`
- 出力: 白文・訓点付き漢文・書き下し文の三段表示

---

## 本日実装したパイプライン

現代語入力
↓ MeCabAdapter          形態素解析 → Token配列
↓ KanbunBNFParser       品詞列解析 → ParseResult
↓ SkeletonBuilder       漢文骨格生成
↓ Ollama（qwen3:8b）   語彙置換 → 漢文白文
↓ KanbunParserService   訓点・書き下し文（Racc接続は次フェーズ）


### 実行例

| 項目 | 内容 |
|------|------|
| 入力 | 王は民を集めて号令した |
| 骨格 | 王 集める 号令する 民 矣 |
| 白文 | 王集民而號令矣 |
| fallback | false |

## BNFパーサー設計

### 背景

Rod­riguez "A BNF Parser in FORTH"（1990）のロジックを
Ruby の recursive descent として実装。
Forth での原理確認 → Ruby 移植という手順を踏んだ。

### コアプリミティブ

```ruby
def term(*pos_types)   # 端末記号マッチ
def seq                # シーケンス（失敗時バックトラック）
def alt(*rules)        # 選択（最初の成功を返す）
def optional(&blk)     # 省略可能要素

対応文タイプ（9種）

sentence_type	例文	漢文構造
:transitive	私は林檎を食べる	我食林檎
:intransitive	犬が走る	犬走
:existential	足がない	無足
:adjectival	馬は速くない	馬不速
:sequential	王は民を集めて号令した	王集民而號令矣
:comparative	馬は牛より速い	馬速莫如牛
使役	王は人を行かせた	王使人行矣
受身	王が臣下に殺された	王被殺於臣下矣
間接格	私は鍵を部屋に忘れた	我忘鍵於室矣

パイプライン上の位置づけ
[BNFパーサー] 日本語品詞列 → 骨格生成   ← 本日実装
[Raccパーサー] 漢文白文   → 返り点付与  ← フェーズ1実装済み

両者は別の問題を解いており、役割分担は最初から成立している。BNFでLRが必要になる左再帰・長距離依存は日本語助詞マーカーが
明示的なため発生しない。

SkeletonBuilder 設計

ParseResult を受け取り、漢文語順の骨格文字列を生成する。

語順規則

文タイプ	骨格語順
通常動詞文	主語 [不] 述語 目的語 [於 間接]
使役	主語 使 目的語 [不] 述語
受身	主語 被 述語 [於 動作主]
存在	有/無 存在物 [於 場所]
形容詞	主語 [不] 述語
連動	主語 V1 V2 ... 目的語
比較	主語 莫如/不若 比較基準 述語

構造マーカー

不 使 被 有 無 莫如 不若 於 矣 乎

MeCabAdapter の工夫

サ変動詞結合（merge_suru_verbs）

MeCabは「号令した」を3トークンに分割する：
号令  名詞-サ変接続 → :noun
し   動詞-自立    → :verb
た   助動詞       → :past

merge_suru_verbs で「名詞-サ変接続 + する系動詞」を
単一 VERB トークンに統合することで解決。

複合動詞結合（merge_compound_verbs）

「おき忘れる」のような連続 VERB を後動詞の base_form で統合。

てしまう除去（merge_shimau_pattern）

完了・遺憾の補助動詞「てしまう」を除去。
意味は前の VERB と PAST マーカーで担保する。

LLM プロンプト設計

モデル選定

モデル	語彙置換タスク
qwen2.5:1.5b	❌ ひらがな残存
qwen3:8b	✅ 安定（採用）

有効な指示形式
【厳守】骨格に準拠した漢字のみ使用すること

原則：否定形指示より肯定・限定形指示が効く。

「〜しないこと」→ 曖昧「〜のみ使用すること」→ 参照先・出力物・範囲が明確

Few-shot 方針

文タイプ別に例を1つずつ選択（最大9例で固定・膨らまない）。
FEW_SHOT_EXAMPLES = {
  transitive:   "骨格：私 食べる 林檎\n白文：我食林檎",
  sequential:   "骨格：王 集める 号令する 民 矣\n白文：王集民而號令矣",
  # ...
}.freeze

NameError: uninitialized constant MeCabAdapter	同上	acronym "MeCab" を追加

次フェーズの課題

	1.	KanbunParserService の Racc 接続
	•	フェーズ1実装済みの否定・禁止句法パーサーと接続
	•	返り点・書き下し文の三段表示を完成させる
	2.	Racc フェーズ2実装
	•	比較（莫如・不若）
	•	選択（与A寧B・寧A無B）
	•	二重否定・疑問・反語
	3.	Few-shot の文タイプ別選択
	•	parse_result.sentence_type を build_prompt に渡す
	•	9種類の例で固定・膨張しない設計
	4.	sanitize_hakubun の動作確認
	•	スペース残存ケースへのバックアップ処理として維持

設計原則まとめ

COBOLのバッチ処理と同じ一方向直列変換。LLMは最初（語彙選択）と必要なとき（フォールバック）のみ担い、あとは決定的なルールで処理する。

	•	BNFパーサー → 日本語構造の解析（前段）
	•	Raccパーサー → 漢文の訓点付与（後段）
	•	LLM → 語彙の漢字変換のみ（中段・最小化）
	•	フォールバック → BNF未対応構文はLLMに全文委譲
