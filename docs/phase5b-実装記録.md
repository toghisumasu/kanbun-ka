# Phase 5b 実装記録

ブランチ `phase5b`（`phase5a` から）。目的：`kakikudashi_exact: true` を「Yomi の自己申告」ではなく「機械検査の結果」にする。
導入前の基準：ベンチ期待白文 50 句のうち exact:true は 41 件（`tmp/exact_before.tsv`、`script/exact_report.rb` で再現）。

## S1 曖昧な受身（パーサーが木に ambiguous を付ける）

- 実装：`Kanbun::Tree::Ambiguous`（Leaf／Seq／Ret に `ambiguous`）、`Tree.ambiguities`、`Tree.clear_ambiguous!`。Racc の規則が付ける：`VERB PREP NOUN`（殺於敵）、`為A V`（所なし。為敵殺・彼為敵殺）。`Yomi` は `Tree.ambiguities` が空のときだけ exact とする（以前は Yomi が木を走査して判定していた）。
- 計画から外れた点：
  1. **見V は exact:true に変更**（指示どおり。phase5a では ambiguous としていた。「見V は Vを見る かもしれない」という曖昧さは残るが、受身の確定形として扱う）。
  2. `Lexicon::LOCATIVE_VERBS`（入 行 去 帰 還 登 在 有 及 成）を新設。於A が行き先・場所で受身にならない動詞は、`VERB PREP NOUN` でも ambiguous にしない（入於深林 などを不必要に落とさないため）。
  3. `被V於A` の内側の `V於A` は受身が確定するので、`clear_ambiguous!` で外す。
  4. `学於人` は保守的に ambiguous のまま（学が他動詞で LOCATIVE_VERBS にないため）。
- 検証：spec 先行（赤 16 件→緑）。RSpec 670 件、conflict 0。exact は 41/50 のまま（phase5a でも 殺於敵 系は false だったため変化なし）。

## S2 復文検査モジュール（Service には未接続）

- 実装：`lib/kanbun/fukubun.rb`（`Kanbun::Fukubun.check(tree, kakikudashi)` → 理由の配列）。`Lexicon` に `OKIJI_TOKENS`・`OKIJI`・`CONTENT_TOKENS` を追加し、置き字・実字の定義はここだけに置いた。
- 検査：実字の欠落／重複（字ごとの出現回数）、読み順（`Kunten.annotate` → `Reorder.reorder` の結果と、書き下しの実字の並びを比較。回数が合っていて順序だけ違うときに報告）、再読文字（1 度目の漢字のあとに `Lexicon::SAIDOKU` の 2 度目の読みが続く）。理由は「字の欠落: 学」「字の重複: 読」「読み順の不一致: 期待 … / 実際 …」「再読文字が2度出ていない: 未」。
- 計画から外れた点：
  1. `見V` の 見 は受身の助動詞（殺さる）として読み、漢字が書き下しに出ない。実字に数えない例外を `FUNCTION_ROLES = [:ukemi_mi]` に置いた（検査側の表。見V が exact:true なので必要）。
  2. 項目 4（重複）は、項目 1 と同じ「字ごとの出現回数」の比較の片側（多い方）として実装した。
  3. 置き字の「除外」は、置き字が `CONTENT_TOKENS` に入らないことで実現している。置き字が書き下しに**出ていること**は検査しない（指示の 4 項目外。累加の「、而も」のように読む而もあるため）。phase5a の `Yomi` にあった置き字検査は S3 で Fukubun に置き換える。
- 検証：spec 先行（赤＝モジュールなし）。正例 28 文（既存の固定文）が違反なし、欠落・重複・字順入れ替え・再読文字の欠けを検出。RSpec 709 件、conflict 0。

## S3 Service への組み込み

- 実装：`KanbunParserService` が `Kanbun::Fukubun.check` を呼び、**exact ＝ Yomi が読みを 1 つに決めている（曖昧でない）かつ 復文検査の違反ゼロ**。返り値のキーは `kakikudashi_exact`・`kakikudashi_reasons`（phase5a の `kakikudashi_notes` から改名）。`Yomi` からは自己検査（`fukubun_problems` など）を取り除き、`Yomi::Result` は `text`・`ambiguities` だけにした。
- S3 だけを戻せば S2（`Fukubun` 単体）が残る単位：S3 のコミットは Service・Yomi・それらの spec だけに触れ、`fukubun.rb`・`lexicon.rb` の追加は S2 に入っている。
- 解釈した点（要確認）：「exact:false のときは暫定出力に警告を付けて返す」を、次のように区別した。
  - **復文検査の違反**：Yomi の書き下しが壊れていると判明しているので、暫定の書き下し（`Kakikudashi.convert`＝漢字を読み順に並べたもの）に戻し、違反を reasons に返す。
  - **曖昧な句形**（殺於敵など）：書き下し自体は読みの 1 つとして妥当なので、Yomi の書き下し（敵に殺す）を返し、曖昧な理由を reasons に付けて exact:false。
  - どちらも暫定出力にする場合は `kakikudashi` の分岐 1 行の変更で済む。
- 辞書にない語（MissingEntry）は従来どおり暫定の書き下し＋理由。
- 検証：spec 先行（赤 6 件→緑）。復文検査の違反を stub で作り、exact:false・暫定出力・理由の返却を確認。RSpec 585 件（phase5a の 25 件スキップ込みの 709 から、Yomi の自己検査 spec を削除した分が減）、conflict 0。

## S5 phase5a の復文検査との突き合わせ（指示漏れの回収）

S2 で検査項目を 4 つに絞った際、phase5a の `Yomi.fukubun_problems` にあった「置き字が書き下しに出ていない」が落ちていた（依頼側の指示漏れ）。5a の全項目を 5b の `Fukubun` に 1 項目ずつ対応づけた。

| # | phase5a `fukubun_problems`／`item_problems` の項目 | 5b `Fukubun` | 状態 |
|---|---|---|---|
| a | 読む順が返り点（`Kunten.reading`）と一致する（書き下し側の表層の並び） | 3 読み順（`Reorder` の順と実字の並び） | 対応あり（ただし比べるのは実字だけ。機能語の順は見ない） |
| b | 置き字が書き下しに出ていない（累加の `:ruika_ji` は例外） | なし → **S5 で追加**（`okiji_reasons`） | **対応なしだった** |
| c | 読む字（実字・機能語とも）が書き下しから落ちていない（与・自・従は助詞移動で例外） | 1 実字の欠落 | **部分的**：実字は対応。機能語（不・之・者・所・其・如…）の取りこぼしは検査していない |
| d | 実字の漢字が書き下しに残っている（項目ごとに `start_with?`） | 1 字の欠落（字ごとの出現回数） | 対応あり（字の数で比べるので、残っていても別の位置にあれば通る点が弱い） |
| e | 再読文字の 1 度目と 2 度目が対になっている | 2 再読文字 | 対応あり（検査の仕方は別：2 度目の読みの出現を見る） |
| — | （5b で新規）字の重複 | 4 字の重複 | 5a になかった |

置き字のほかに対応のない項目：**c の機能語の取りこぼし**（部分的）。`Fukubun` は書き下し全体の文字列しか見ないため、機能語は仮名で出る（不→ず、所→る所）ので、項目ごとの出力が必要になる。`Fukubun` に入れるには `Yomi` が項目ごとの出力を返す変更が要り、S5 の範囲（置き字）を超えるので入れていない。**未実装として残す。**

### 置き字の検査（S5）
- 構文木の沈黙した葉（`silent?`、`:ruika_ji` を除く）の字が書き下しに出ていれば「置き字が書き下しに出ている: 焉」。ほかに同じ字を読む語（非沈黙の葉）がある分は許す。
- 例外：累加の 而（`:ruika_ji`、「、而も」）。与A・自A・従A の助詞移動は、字が沈黙でなく機能語なので置き字の検査の対象外（5a での例外は c の側にあたる）。
- 置き字の定義は `Lexicon` の沈黙フラグ（構文木）で、`Fukubun` に新しい字の一覧は持たない。

### yomi_spec から消えた describe/it と行き先
| 消えた spec | fukubun_spec 等の同等 | 扱い |
|---|---|---|
| 読む順が返り点と食い違えば検出 | 「3. 読み順」（我読漢文・不読書） | 同等あり |
| 実字の漢字が落ちていれば検出 | 「1. 実字の欠落」 | 同等あり |
| 再読文字の 1 度目と 2 度目が対 | 「2. 再読文字」 | 同等あり |
| 見V は受身か決まらない | 反転済み（`見殺` は曖昧でない・exact:true。ご指示） | 復活しない |
| 置き字が書き下しに出ていれば検出 | なし | **復活**（「5. 置き字」） |
| ベンチの期待白文＋固定文が検査に通る（コーパス網羅） | 固定 28 文のみ | **復活**（Yomi の書き下しに対して `Fukubun.check`、書けないものは skip） |
| 項目ごとの「落ちています」（機能語の欠落） | なし | 復活せず（上記 c。`Yomi` の項目ごとの出力が必要） |

## S6 機能語の欠落と実字の位置（項目ごとの検査）

- 実装：`Yomi::Result` に `parts`（`Yomi::Piece = 葉・2度目か・書き下し断片`、読む順、つなぐと `text`）を追加。`Fukubun.check(tree, kakikudashi, parts: nil)` は parts があれば項目単位の検査（`part_reasons`）を足す。Service は `parts: result.parts` を渡す。parts なしの呼び出し（S2 の spec）は従来どおり。
  - 読む字の断片が空なら「機能語の欠落: 不」（実字なら「実字の欠落」。1 で「字の欠落」を報告済みの字は重ねて出さない）。与・自・従は 5a と同じく例外。
  - 実字の断片がその漢字で始まらなければ「実字の位置: 読」（別の位置に同じ字があっても通さない）。
  - 断片をつないだものが書き下しと違えば「書き下しと項目の断片が一致しません」。
- 5a との対応表（S5 の表）の更新：

| # | 5a の項目 | 5b（S6 後） |
|---|---|---|
| c | 読む字が落ちていない（与・自・従は例外） | 対応あり（`part_reasons`。実字は 1 とも二重に見る） |
| d | 実字の漢字が項目に残っている | 対応あり（項目単位。字数だけでなく位置まで見る） |
| a | 読む順 | 3（実字）に加え、項目単位でも欠落・位置を見る。機能語の**並び順**自体は 5a も項目の並びを返り点側と照合しており、5b は実字の順で照合する（機能語の順の取り違えは、欠落・位置の検査を通る限り構造上起きにくい） |

## S7 曖昧な受身を暫定出力に統一する

- 実装：`KanbunParserService#kakikudashi` の分岐を 1 か所だけ変更。復文検査の違反と Yomi の曖昧（`ambiguities`）をまとめて `problems` とし、あれば暫定出力（`interim`）＋ reasons、なければ Yomi の書き下し・exact:true・理由なし。`Yomi::Result#exact?` は Service からは使わなくなった（Yomi 側には残す）。
- 殺於敵・為敵殺・学於人 は暫定出力（例：殺於敵 → 「敵殺」）・exact:false・理由つき。確定した受身（彼為敵所殺・見殺・被殺於敵）は書き下しのまま exact:true、理由は空。
- 計画から外れた点（reasons の経路）：
  1. この Rails アプリには画面（controller/view）も HTTP API（routes）もない。呼び出し経路は `KanbunParserService.call` と `KanbunTranslatorService.call`（→ `script/kanbun_repl.rb`）だけである。
  2. 確認の結果、`KanbunTranslatorService::Result` は `kakikudashi_exact`・`kakikudashi_reasons` を**捨てていた**（phase5a から）。reasons が呼び出し側に届かないので、`Result` に 2 フィールドを足して通した（spec 先行）。`kanbun_repl.rb` は暫定のとき「（暫定）」と理由を表示するようにした。
  3. `kanbun_translator_service_jp.rb`（旧版の同名クラス定義）には触れていない。
- 検証：spec 先行（赤 5 件→緑）。RSpec 726 件・0 失敗・pending 25（増減なし）、Racc conflict 0、ベンチ 一致率 48/50・exact:true 41/50（減った文 0、導入前後で同じ）。実際の呼び出し：`KanbunParserService.call("殺於敵")` → 「敵殺」・exact:false・理由あり、`彼為敵所殺` → 書き下し・exact:true。`kanbun_repl.rb`（実 Ollama・MeCab）で「彼は敵に殺された」→ 白文 彼殺於敵 → 「彼敵殺（暫定）」＋理由行を表示、「私は漢文を読む」→ 書き下し（理由なし）。

## S8 何独の読みの修正と、読みの表の監査

- 監査（修正前、`bin/rails runner script/lexicon_audit.rb`）：副詞表 31・ADJS 30・SAIDOKU_SECOND 8・VERBS 78 項目を検査（A 送り仮名に漢字／B 自分の表層形と重複／C ほかの語にも同じ字）。**重複の疑いは 1 件だけ**：`ADVS['何独'] => 'ぞ独り'`（A・B・C すべて該当。C は 非独・不独・独）。同種の項目は他になく、一覧で報告すべきものはなかった。
