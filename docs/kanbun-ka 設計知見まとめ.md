# kanbun-ka 設計知見まとめ

2026-09-19

## プロジェクト概要

**kanbun-ka**（漢文化）は、現代日本語を古典漢文（文言文）に自動変換するRails Webアプリケーション。

- リポジトリ: `toghisumasu/kanbun-ka`
- 出力: 白文・訓点付き漢文・書き下し文の三段表示
- 品質基準: 白楽天詩集（武部利男訳、平凡社ライブラリー）の白雲期を原文対照ベンチマークとする
- 着想: 魚返善雄『漢文の学び方』の「漢文は符号語（暗号）」論——現代語→漢文変換はロスのある符号化（エンコード）と捉える

## 三層パイプライン設計

```
口語体日本語
    ↓ LLM（Ollama / qwen2.5:7b）
      役割：語彙選択・漢文的表現への変換・文語体化
文語体漢語列
    ↓ 辞書参照
      役割：多義字の品詞決定（之・者・不など）
漢文白文
    ↓ LRパーサー（Racc）
      役割：構文木生成 → 返り点・送り仮名の自動付与
訓点付き漢文
```

**設計思想**: COBOLのバッチ処理と同じ一方向直列変換。LLMは最初の一段階のみ担い、あとは決定的なルールで処理することでローカルLLMの負担を最小化する。

## LRパーサーの適用根拠

- 漢文は語順が厳格でCFG（文脈自由文法）で十分に記述できる範囲に収まる
- 基本構文パターン（主語+述語、否定・使役・受身など）は有限のBNF規則で書ける
- 返り点は構文木の後順走査（post-order traversal）で自動付与できる
- 句法パターン80種（国語句法一覧①②）の7〜8割は文脈なしで構造が決定できる定型パターン
- 実装にはRuby標準添付のRacc（YaccのRuby実装）を使用

**自然言語との違い**: 文語日本語（係り結びなど長距離依存）と違い、漢文はLR(1)でシンプルに処理できる

## 多義字問題と対処方針

漢文パーサーの核心的難題。「書」（書く/書物）「之」（代名詞/構造助字/動詞）「与」（並列/疑問/選択）など、文脈によって品詞が変わる文字が多数ある。

**MeCab・KNP/JUMANが使えない理由**: これらは現代・古典日本語の形態素解析器。「不学」を日本語熟語として認識し、漢文文法の「不＋動詞」パターンを解析できない。送り仮名がないと動詞と認識できないという根本的な不一致がある。

**対処方針（軽い順）**:

1. LLM（Ollama）に品詞タグ付けを依頼——環境がすでにある
2. Rubyの辞書Hash——頻出パターン数十種を手書き
3. GuwenBERT（Python連携）——古典中国語専用、最高精度だが最重量

**当面の方針**: まず辞書Hashで対応し、精度不足の場合にLLM補助を追加する

## 句法実装フェーズ分類

国語句法一覧①②（全80句法）をLRパーサー実装の難易度で三段階に分類する。

**フェーズ1：前置・単純パターン（多義字なし）**
否定（不・弗・非・無・莫）、禁止（莫・勿）、使役（使・令・命）、仮定（若・如・雖）

**フェーズ2：二項・三項パターン**
比較（莫如・不若）、選択（与A寧B・寧A無B）、二重否定、部分否定、抑揚（況〜乎）

**フェーズ3：多義字が絡むパターン（LLM補助が必要）**
与（並列/疑問/選択）、独（限定/反語）、何（6種の読み分け）、疑問・反語全般

フェーズ1から順に実装・検証し、動作確認後に次フェーズへ進む。
